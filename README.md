# Лабораторная работа №4 — локальное состояние React

Ветка: `24`. Предметная область — система совместного редактирования документов.
Автономный клиент находится в **frontend/**. Файлы REST API из лабораторной №3 сохранены;
для этой работы запуск сервера, база данных, JWT и `.env` не требуются.

## 1. Что нужно установить

- Git.
- Node.js **20.19+ или 22.12+** и npm (устанавливается вместе с Node.js).
- Для серверной части — доступ к PostgreSQL проекта в Supabase.
  Для интерфейса лабораторной №4 база не нужна.

Проверка в терминале:

```bash
git --version
node --version
npm --version
```

Команды ниже рассчитаны на Bash: Linux, WSL, macOS или Git Bash.

## 2. Клонирование проекта

В папке, где хотите разместить проект:

```bash
git clone --branch 24 https://github.com/Eugenemihalk/project.git
cd project
git branch --show-current
```

Последняя команда должна показать `24`. Если репозиторий уже склонирован,
перейдите в его корневую папку и выполните:

```bash
git fetch origin
git switch 24
```

Если локальной ветки ещё нет, но есть `origin/24`, команда `git switch 24`
создаст отслеживающую ветку автоматически. Если Git сообщает, что удалённой ветки
`24` нет, её сначала нужно отправить из рабочей копии с готовой лабораторной:
`git push -u origin 24` после фиксации изменений. Ветка `23` содержит сервер
прошлой лабораторной и не содержит новый React-клиент.

## 3. Запуск лабораторной №4: React-интерфейс

Все команды этого раздела начинаются **из корня репозитория `project/`**.

```bash
cd frontend
npm ci
npm run dev
```

`npm ci` устанавливает зависимости по `package-lock.json`. При отсутствии
этого файла используйте `npm install`.

Откройте **http://localhost:5173**. Если порт занят, Vite выведет другой адрес —
используйте адрес из терминала. Терминал с сервером разработки оставьте открытым.
Через секунду должны появиться два примера документов.

**Для этой лабораторной `.env` заполнять не нужно.** Не создавайте
`frontend/.env`: приложение не обращается к серверу и хранит документы в
localStorage браузера. Supabase, JWT и запуск Express для этого режима не нужны.

Повторный запуск после установки зависимостей:

```bash
cd frontend
npm run dev
```

Эти команды также выполняются из корня репозитория. Если уже находитесь
в `frontend/`, выполняйте только `npm run dev`. Остановка — `Ctrl+C`.

### Проверка и сборка клиента

В отдельном терминале из корня репозитория:

```bash
cd frontend
npm test
npm run build
```

Сборка появляется в `frontend/dist/`. Для просмотра собранной версии,
находясь в `frontend/`, выполните:

```bash
npm run preview
```

Обычно адрес предпросмотра — **http://localhost:4173**; точный адрес выводится
в терминале. Для сдачи достаточно dev-сервера и успешной сборки.

## 4. Если нужен сервер лабораторной №3

Этот раздел нужен для отдельной проверки REST API. React-клиент лабораторной
№4 пока не подключён к нему: данные в браузере и в PostgreSQL независимы.
Оба процесса можно запускать одновременно в разных терминалах.

### Шаг 1. Установить серверные зависимости

Откройте новый терминал **в корне репозитория `project/`**, где лежат `server.js`,
`package.json` и `.env.example`:

```bash
npm ci
```

### Шаг 2. Создать `.env` в корне

Файл `.env` не хранится в Git, поэтому после клонирования его нужно создать.
Если файл уже есть, сохраните свои значения. В Bash команда ниже копирует
пример только при отсутствии `.env`:

```bash
cp -n .env.example .env
```

В PowerShell файл можно создать через проводник или редактор, скопировав
содержимое `.env.example`. Откройте **`project/.env`** и заполните три переменные:

```dotenv
DATABASE_URL=postgresql://postgres:YOUR_DB_PASSWORD@db.YOUR_PROJECT_REF.supabase.co:5432/postgres
JWT_SECRET=YOUR_GENERATED_RANDOM_SECRET
PORT=7000
```

| Переменная | Что указать |
|---|---|
| `DATABASE_URL` | Полную строку подключения PostgreSQL вашего проекта Supabase с настоящим паролем базы |
| `JWT_SECRET` | Случайную строку длиной не менее 32 символов для подписи JWT |
| `PORT` | Порт Express; для примеров используется `7000` |

Для `DATABASE_URL` возьмите строку подключения PostgreSQL из своего проекта
Supabase. Замените плейсхолдер пароля на **пароль базы данных**. Это не пароль
аккаунта Supabase, не `anon`-ключ и не `service_role`-ключ. Если в вашей строке
другие хост, порт или имя пользователя, сохраните их: копируйте строку целиком,
а не подставляйте параметры из примера наугад. Если прямое подключение недоступно
из вашей сети, используйте строку session pooler, предоставленную вашим проектом.
Если строка содержит параметры подключения, сохраните их тоже.

Специальные символы в пароле внутри URL должны быть URL-кодированы:
например, `@` → `%40`, `#` → `%23`, `%` → `%25`. Пароль с символами `#`
нельзя оставлять в `.env` как незакодированную часть URL.

Для генерации `JWT_SECRET` выполните:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Скопируйте полученную строку из 64 символов после `JWT_SECRET=`. Уберите
`YOUR_DB_PASSWORD`, `YOUR_PROJECT_REF` и `YOUR_GENERATED_RANDOM_SECRET`:
это обозначения для примера, с ними сервер работать не будет. После изменения
`.env` перезапустите сервер. Файл `.env` уже исключён из Git.

### Шаг 3. Применить миграции

В корне репозитория после заполнения `.env`:

```bash
npm run db:migrate
```

Миграции создадут таблицы документов и пользователей в базе из `DATABASE_URL`.
Если миграции уже применены, повторный запуск не создаст таблицы заново.

Необязательно, **один раз для заполнения базы примерами**:

```bash
npx sequelize-cli db:seed:all
```

Сидер добавляет два документа. Повторный запуск может добавить дубликаты.
Примеры React-клиента создаются отдельно и не зависят от этого сидера.

### Шаг 4. Запустить API

В корне репозитория:

```bash
npm start
```

Для разработки с автоматическим перезапуском вместо `npm start`:

```bash
npm run dev
```

При успешном подключении к PostgreSQL появится сообщение
`Server running on http://localhost:7000`. Если изменили `PORT`,
используйте свой порт во всех запросах.

Express здесь предоставляет JSON API. Главной HTML-страницы на порту 7000 нет:
открывать React-интерфейс нужно на порту 5173.

### Шаг 5. Проверить API в Postman

1. Создайте запрос `POST http://localhost:7000/auth/register`.
   Выберите Body → raw → JSON и отправьте:

   ```json
   { "email": "student@example.com", "password": "TestPassword123!" }
   ```

   Ожидается `201`. Если аккаунт уже есть, ответ `409`; переходите ко входу.

2. Отправьте `POST http://localhost:7000/auth/login` с тем же JSON.
   Из ответа скопируйте значение `token`.

3. Для `GET http://localhost:7000/profile` выберите Authorization → Bearer Token
   и вставьте токен. Ожидается `200` с профилем.

4. Аналогично выполните `GET http://localhost:7000/documents` с Bearer Token.
   Создание выполняется через `POST /documents` с тем же токеном и JSON:

   ```json
   { "title": "План проекта", "content": "Содержание документа", "status": "draft" }
   ```

5. Для редактирования используйте `PUT /documents/<id>` с JSON, содержащим
   `title`, `content` и при необходимости `status`.

6. Для удаления нужен администратор. После регистрации пользователя выполните
   **в отдельном терминале из корня репозитория**:

   ```bash
   npm run set-admin -- student@example.com
   ```

   Затем `DELETE /documents/<id>` с токеном этого пользователя вернёт `204`.
   Обычный пользователь получит `403`.

Токен действует один час. При истечении срока выполните вход повторно.
Успешная регистрация не назначает роль администратора автоматически.

## 6. Если что-то не запускается

| Ошибка или ситуация | Что сделать |
|---|---|
| `vite: not found` или отсутствует модуль React | В `frontend/` выполнить `npm ci` |
| Ошибка версии Node.js (`EBADENGINE`) | Проверить `node --version`, использовать Node.js 20.19+ или 22.12+ |
| Вместо интерфейса запускается nodemon | Выполнить `cd frontend`, затем `npm run dev` |
| `Не задана переменная окружения DATABASE_URL` | Создать `.env` в корне репозитория и заполнить строку PostgreSQL |
| `Задайте JWT_SECRET длиной не менее 32 символов` | Сгенерировать секрет, заполнить `.env` и перезапустить API |
| Ошибка подключения к PostgreSQL | Проверить всю строку подключения, пароль, доступность базы и сети; при необходимости использовать session pooler своего проекта |
| Таблица не найдена (`relation ... does not exist`) | Выполнить `npm run db:migrate` в корне с тем же `.env` |
| `401` от `/documents` | Передать действующий Bearer Token, при необходимости повторить вход |
| `403` при удалении | Назначить зарегистрированному пользователю роль admin |
| Порт занят (`EADDRINUSE`) | Для API изменить `PORT` в `.env`; для Vite использовать адрес, который он выведет при запуске |
| После открытия другого порта нет старых документов | localStorage привязан к origin: браузеру, протоколу, хосту и порту. Открыть прежний адрес |
| `407 Proxy Authentication Required` при установке npm-пакетов | Проверить настройки и авторизацию сетевого прокси; это ошибка загрузки зависимостей |

## Что реализовано

- Создание, просмотр, редактирование и удаление документов с подтверждением.
- Поля модели: `id`, `title`, `content`, `status`, `createdAt`, `updatedAt`.
  Статусы: `draft` (черновик) и `published` (опубликован).
- Контролируемые поля формы на useState. Название от 3 до 255 символов,
  текст обязателен. Enter в поле названия отправляет форму, если она заполнена.
- Поиск по названию и тексту без учёта регистра, фильтр по статусу,
  сортировка по названию, дате создания или изменения. Сортировка запоминается.
- useEffect с [] загружает список с задержкой 1000 мс; отдельный эффект
  сохраняет изменения после завершения загрузки. У каждого таймера есть очистка.
- localStorage: `collab.documents` — список, `collab.list.sort` — сортировка,
  `collab.draft.new` / `collab.draft.<id>` — несохранённая форма.
- При отсутствии или повреждении списка загружаются два примера. Сохранённый
  пустой массив остаётся пустым. Ошибка записи отображается пользователю.
- Автосохранение формы через 500 мс после последнего изменения (debounce).
  После перезагрузки черновик восстанавливается; его можно сбросить.
  Успешное сохранение документа удаляет черновик.
- Заголовок вкладки отражает количество документов; статистика вычисляется через useMemo.
- Адаптивная разметка для компьютера и телефона.

Совместное редактирование в реальном времени и серверная авторизация относятся
к дальнейшим этапам проекта. В этой работе данные хранятся в текущем браузере.

## Проверка

```bash
cd frontend
npm test
npm run build
```

В браузере:

1. Убедиться, что после секунды загрузки появились два примера.
2. Создать документ, открыть его, изменить текст и статус.
3. Проверить поиск, фильтр статуса и все три способа сортировки.
4. Перезагрузить страницу: список и выбранная сортировка сохраняются.
5. Начать новый документ, подождать 500 мс, перезагрузить редактор:
   появляется восстановленная форма. Проверить «Сбросить черновик».
6. Удалить документ, отменить другое удаление. После удаления всех документов
   и перезагрузки список остаётся пустым.
7. В DevTools → Application → Local Storage проверить JSON по ключу
   `collab.documents`. Повреждённый JSON после перезагрузки заменяется примерами.

После проверки зафиксируйте изменения и отправьте ветку `24` из корня репозитория:

```bash
git add frontend README.md docs
git commit -m "Лабораторная 4: React, состояние и localStorage"
git push -u origin 24
```
