# Практическое занятие №1 — Middleware и шаблонизаторы

Ветка: `pz21`. Тема: система совместного редактирования документов.
Проект написан заново для этого ПЗ: Express + EJS, документы хранятся в массиве в памяти.
В рамках задания реализованы просмотр и добавление документов. Совместное редактирование
в реальном времени не реализуется. База данных, миграции и JWT не нужны.

## 1. Как запускать

Нужны Node.js 20 или новее и npm.

```bash
git switch pz21
npm ci
npm start
```

Откройте **http://localhost:7000**. Остановка: `Ctrl+C`.
Если порт занят, задайте другой (Bash):

```bash
PORT=7001 npm start
```

`.env` не используется. После перезапуска добавленные документы исчезают,
а исходные два документа снова загружаются из `data/documents.js`.

## 2. Как проверить в браузере

1. Откройте `/`: отображается список документов.
2. Нажмите название: `/item/1` показывает данные конкретного документа.
3. Откройте `/add` без параметров: сервер перенаправит на `/login`.
4. Перейдите по ссылке учебного входа: `/add?auth=1` показывает форму.
5. Заполните название и содержимое и нажмите «Добавить»: после `POST /add?auth=1`
   сервер перенаправит на `/`, новый документ появится в списке.
6. Откройте `/unknown` или `/item/999`: появится страница 404.
7. Посмотрите консоль сервера: каждый завершённый запрос записывается с временем,
   методом, URL, статусом и длительностью в миллисекундах.

Для проверки 500 без дополнительного маршрута можно временно переименовать
`views/index.ejs` в `views/index.ejs.bak` и открыть `/`. Express не найдёт шаблон,
передаст ошибку обработчику, а тот выведет `500.ejs` со статусом 500 и запишет ошибку
в консоль. Затем верните имя `index.ejs` и откройте главную снова.

## 3. Как разбираться в коде

Начните с `server.js`, затем посмотрите маршруты, контроллеры и шаблоны.

| Файл | Что делает |
|---|---|
| `server.js` | Создаёт приложение, настраивает EJS и подключает middleware по порядку |
| `data/documents.js` | Общий массив документов с полями `id`, `title`, `content` |
| `routes/documents.js` | Сопоставляет методы и URL с контроллерами; защищает форму и добавление |
| `controllers/documentsController.js` | Читает массив, передаёт данные в EJS, проверяет форму и добавляет документ |
| `middleware/logger.js` | Записывает время, метод, URL, статус и длительность запроса |
| `middleware/auth.js` | Проверяет `req.query.auth`, устанавливает `req.user` или делает редирект |
| `middleware/errors.js` | Возвращает HTML-страницы 404 и 500; логирует ошибки |
| `views/index.ejs` | Выводит список документов через цикл |
| `views/item.ejs` | Показывает документ по ID |
| `views/add.ejs` | Выводит форму, имя пользователя и сообщение при пустых полях |
| `views/login.ejs` | Объясняет имитацию входа и даёт ссылку с `auth=1` |
| `views/404.ejs`, `views/500.ejs` | Отдельные страницы ошибок |
| `views/partials/` | Общие начало и конец HTML-страницы |

### Порядок обработки запроса

`logger → express.urlencoded → маршруты → notFound → errorHandler`.

Логирование вызывает `next()`, чтобы продолжить обработку. Событие `finish`
позволяет записать итоговый статус и длительность после отправки ответа.
`express.urlencoded()` разбирает поля HTML-формы и помещает их в `req.body`.
На `/add` перед контроллером дополнительно вызывается `auth`.
Если подходящий маршрут или документ не найден, запрос доходит до `notFound`.
Если возникает ошибка, Express передаёт её обработчику с четырьмя параметрами:
`(error, req, res, next)`.

### Как данные попадают в HTML

Например, контроллер главной страницы вызывает:

```js
res.render('index', { title: 'Документы команды', documents });
```

EJS получает переменные `title` и `documents`. В шаблоне `<% ... %>` выполняет
JavaScript (циклы и условия), `<%= ... %>` выводит значение с HTML-экранированием.
Пользовательские название и содержимое выводятся именно через `<%= ... %>`.
`<%- include('partials/header') %>` подключает готовый HTML общего заголовка.
Отдельный layout-пакет не нужен: в задании разрешены partials.

### Как работает имитация авторизации

Только значение `auth=1` пропускает запрос к форме и добавлению.
При успехе middleware записывает `req.user = { name: 'Участник команды' }`.
Форма отправляется на `/add?auth=1`, чтобы параметр сохранялся при POST.
Без него оба маршрута перенаправляют на `/login`.
Это учебная проверка параметра, а не реальная защита учётных записей.

## 4. Что сделано по заданию

| Часть ПЗ | Реализация |
|---|---|
| 1. Настройка Express и EJS | Зависимости `express`, `ejs`; `view engine` и абсолютный путь `views` в `server.js` |
| 2. Шаблоны | `index.ejs`, `item.ejs`, `add.ejs`; общий каркас через `partials/header.ejs` и `partials/footer.ejs` |
| 3. Логирование | `middleware/logger.js`: время запроса, метод, URL и длительность |
| 3. Имитация авторизации | `middleware/auth.js`: проверка `?auth=1`, редирект `/login`, передача `req.user` форме |
| 4. `GET /` | Список документов из массива |
| 4. `GET /item/:id` | Детальная страница документа; неизвестный ID даёт 404 |
| 4. `GET /add` | Форма добавления после проверки авторизации |
| 4. `POST /add` | Добавление в массив и редирект на главную; пустые поля дают 400 с повторным выводом формы |
| 4. Данные без БД | Массив в `data/documents.js`, доступный контроллерам |
| 5. Ошибка 404 | Последнее обычное middleware рендерит `404.ejs` со статусом 404 |
| 5. Ошибка 500 | Error-handling middleware логирует ошибку и рендерит `500.ejs` со статусом 500 |

Отчёт, PDF, скриншоты и ответы на контрольные вопросы в этот проект не включены.
